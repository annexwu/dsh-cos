# 插件 COS 云存储操作

本文档定义插件 COS 云存储场景的路径语义和操作流程。“云盘”是该场景的历史名称；用户使用“云存储”或“云盘”时，都按本文档执行。AI 对外回复统一优先使用“COS 云存储”或“云存储”，只有解释兼容关系或引用用户原话时才使用“云盘”。

只要用户明确提到“云存储”“当前云存储”“我的云存储”，或使用“云盘”“当前云盘”“我的云盘”，或上文已经通过任一名称确定当前操作对象是插件 COS 云存储，即使本轮只说“同步这些产物”“上传一下”“下载它”，也按本文档执行，不要退回账号级通用 COS 流程。

## 一、先读取云存储配置

首先通过 `tencentcloud_cos_storage_manage` 调用：

```json
{ "Action": "help", "Parameters": {} }
```

从 `DefaultCloudStorage` 读取：

- `Configured`、`CredentialsConfigured`
- `Bucket`、`Region`
- `Prefix`、`StorageRootUri`
- `CustomDomain`

`DefaultCloudStorage` 表示当前插件 COS 云存储配置，`StorageRootUri` 是拼接 Bucket 与 Prefix 后的根路径。配置不完整或凭证不可用时，引导用户前往插件设置，不索取凭证内容。

`Prefix` 是插件云存储根目录对应的 COS Key 前缀，不是可忽略的筛选条件。用户看到的云存储相对路径必须映射为：

```text
对象 Key = Prefix + 云存储相对路径
```

不要猜测、替换、重复拼接或遗漏 `Prefix`。调用通用 Action 时显式传入 `Bucket` 和 `Region`。

## 二、同步工作区产物

用户说“同步产物到云存储”“上传生成结果”“备份当前工作区”等，但没有指定云存储目标子目录时，目标路径尚未确定，不能开始上传。用户沿用历史名称“云盘”提出相同要求时，也执行以下流程。

1. 先确定需要同步的工作区文件和相对路径。
2. 询问用户要放到哪个云存储子目录；可以同时给出建议目录 `<工作区名称>/<会话名称>/`，并展示拼接 `Prefix` 后的完整对象 Key 前缀。
3. 工作区名称只取目录名，不暴露本机绝对路径；会话名称只使用当前会话已有的简短名称。没有可靠会话名称时只询问目录，不使用日期、随机串或自造名称代替。
4. 用户回复确认建议目录或给出自定义目录前，不调用 `upload`。
5. 目标目录确定后，保留工作区相对目录结构。例如源文件 `reports/index.html` 应上传为 `<Prefix><目标子目录>/reports/index.html`，不能只取文件名。
6. 每次 `upload` 都必须显式传入完整 `key`。不能省略 `key` 让底层按文件名上传。
7. 上传前列出目标目录、文件数量、目标 Key，并说明同名对象可能被覆盖；等待用户在后续消息中明确确认后再上传。
8. 只有用户明确要求上传到云存储根目录时，才允许目标目录为空；仍要说明文件会直接散放在根目录并等待确认。
9. 上传完成后汇总成功和失败项，至少给出对象 Key；不要输出本机绝对路径或带认证信息的签名 URL。

推荐询问方式：

```text
准备同步 4 个产物。建议放到 COS 云存储的 `dsh-cos/本次产物/`，对应对象前缀为 `test1/dsh-cos/本次产物/`。是否使用这个目录，还是指定其他云存储子目录？
```

用户最初的“帮我同步/上传”只是提出任务，不等于确认尚未展示的路径和覆盖范围。

## 三、浏览、查询与链接

- 浏览目录：使用 `list`，`prefix` 为 `Prefix + 云存储相对目录`。
- 查询属性：使用 `head`，`key` 为映射后的完整对象 Key。
- 获取临时链接：使用 `sign-url`，只在用户需要时生成；不要在回复中泄露签名参数。
- 分页结果存在下一页标记时继续查询，直到覆盖用户指定范围。

## 四、上传与下载单个文件

- 上传工作区文件：使用 `upload`，`file` 必须是当前工作区相对路径，`key` 必须是映射后的完整对象 Key。
- 下载到工作区：使用 `download`，`output` 必须是当前工作区相对路径；默认不覆盖已有文件。
- 用户未给上传目标路径时先询问，不得用源文件名直接落到 `Prefix` 根目录。
- 用户未给下载保存路径时，应提出明确的工作区相对路径并在写入前确认。

## 五、删除

1. 先用 `list` 或 `head` 确定精确对象 Key。
2. 目录删除必须完整分页枚举对象，展示 Key、数量和总大小。
3. 明确说明删除不可恢复，等待用户在后续消息确认。
4. 只删除刚才展示并确认的精确 Key；不要再次按前缀扫描后扩大范围，也不要删除或清空 Bucket。

## 六、Action 对照

| 云存储操作 | 通用 Action |
| --- | --- |
| 浏览目录 | `list` |
| 查看属性 | `head` |
| 上传工作区文件 | `upload` |
| 下载到工作区 | `download` |
| 获取临时链接 | `sign-url` |
| 删除文件 | `delete` |
| 删除已确认的一组对象 | `delete-multiple` |

插件 COS 云存储是一套基于 `DefaultCloudStorage` 的路径和交互约定，不是另一套 Tool 或 Action。执行仍只使用 `tencentcloud_cos_storage_manage`。
