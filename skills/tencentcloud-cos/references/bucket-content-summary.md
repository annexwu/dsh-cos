# 场景 SOP：桶 / 目录文件内容总结

> 本文件是 SKILL「场景六：桶 / 目录文件内容总结」的完整执行流程（SOP），从主 SKILL 抽出以减少干扰。
> 触发场景：用户说「总结下这个桶 / 目录里的文件」「这批文件都讲了什么」「概览一下 `album/` 下的内容」等，需要对**一批文件**做内容层面的归纳。

## 目标

对指定桶 / 前缀目录下的文件，结合用户的关注点（如"讲了什么主题""有哪些人物 / 场景""财务相关的重点"），产出一份**内容总结**。核心是：先圈定文件、再对每个文件拿到"内容摘要"、最后汇总。

## 四步流程

### 第 1 步：查绑定了什么数据集

先用 `find-datasets-by-bucket` 查目标桶 / 目录**绑定了哪些数据集**，并确认每个数据集的**模板类型**（ImageSearch / VideoSearch / DocSearch / 简单检索等）——模板决定第 3 步能用哪种摘要手段。

```bash
node scripts/ci_api.mjs find-datasets-by-bucket --appid <AppId> --region <r> --bucket <bucket-appid>
```

- 命中数据集且绑定路径覆盖目标目录 → 走「有数据集」分支（第 2 步）。
- 没有数据集 / 目标路径不在绑定目录 → 走「无数据集兜底」：直接用 COS `GetBucket` 列文件，再对每个文件按第 3 步的兜底手段取摘要（图片 `image-analysis`+`image-exif`、纯文本直接拉取内容）。

### 第 2 步：按条件检索 + 分散采样出文件列表（≤20 个）

有绑定数据集时，按用户提问的条件调用数据检索接口过滤出候选文件：

- 元数据条件（类型 / 大小 / 时间 / 标签等）→ `simple-query`（映射见 `dataset-simple-query.md`）。
- 语义条件（"和 XX 相关的图 / 文档 / 视频"）→ 对应模板的 `image-search` / `doc-search` / `video-search`。

**关键：控制样本量、按维度分散采样。** 文件数量多时不要全量处理，尽量在**不同维度分散地采样出 <20 个文件**，让样本更有代表性：

- 维度示例：文件类型（`MediaType` / `ContentType`）、时间（`CreateTime` 分时间段）、自定义标签（`CustomLabels.*`）、路径前缀、大小分档等。
- 做法建议：先用 `simple-query` 的 `Aggregations`（`group`）看各维度的分布，再按分布**在每个分组里各取几个**（round-robin / 分层抽样），凑够但不超过 20 个。
- 若用户明确限定了范围（如"只看 `album/2026/` 下的图片"），在该范围内采样即可。

### 第 3 步：逐文件获取内容摘要

对采样出的每个文件，按其类型与所属数据集模板选摘要手段：

| 文件 / 数据集情况 | 取摘要手段 | 拿到的信息 |
| --- | --- | --- |
| 已加入智能检索，并在图片 / 视频模板数据集中完成入库的媒资 | `get-ai-media-info`（按 URI 拉单文件 AI 详情） | AI 标签 / ASR 台词 / OCR 文字 / 粗分类（视频含时间片段） |
| 图片（无合适数据集，或想补充理解） | `image-analysis`（`ImageLabels` 打标或 `Custom` 提问） | 整体描述 + 分层标签 / 按 prompt 的回答 |
| 图片（要客观元信息） | `image-exif` | 拍摄时间 / 相机型号 / GPS / 尺寸等 EXIF |
| 可能是纯文本后缀的文件（`.txt/.md/.json/.csv/.log/.xml/.yaml/.html` 等） | 直接拉取对象内容 | 原文文本，自行阅读理解 |

说明：
- `get-ai-media-info` **仅支持已加入智能检索，并在 ImageSearch / VideoSearch 数据集中完成入库的目标文件**；仅存在同桶数据集不代表文件已入库，DocSearch 数据集不要用它。
- 图片可同时取 `image-analysis`（语义）+ `image-exif`（元信息）互补。
- 文本文件优先直接读内容；体积过大时只读头部若干 KB 做概括。

### 第 4 步：汇总成内容总结

把每个文件拿到的信息（AI 标签 / 描述 / 台词 / EXIF / 正文要点）按**用户的需求角度**归纳：

- 用户问"讲了什么" → 提炼主题 / 高频标签 / 代表性内容。
- 用户问"有哪些人物 / 场景 / 物体" → 汇总标签与描述中的实体。
- 用户问"财务 / 某专题相关" → 只保留命中该专题的文件并展开。

输出建议：先给整体结论（这批文件主要是什么），再按维度或代表文件列要点，必要时标注"基于 N 个采样文件（共 M 个）"以说明是抽样结论。

## 注意事项

1. **先路由再动手**：本流程属于「场景一：资源检索决策」中"要看懂内容"的展开；能用数据集就用，用不了再兜底。
2. **控量优先**：默认样本上限 20 个，避免大量串行调用；用户要"逐个精确"再放开并说明成本。
3. **模板匹配**：第 3 步严格按数据集模板选接口（见 `dataset-search.md` 顶部的模板↔接口对照）。
4. **抽样透明**：结论基于抽样时，明确告知采样口径，避免误导。
